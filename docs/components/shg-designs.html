How to read and reuse this archive

DWG is the byte-identical source. DXF.gz is an ASCII DXF export compressed for download; decompress it before opening it in CAD software. SVG, PDF and PNG are preview derivatives. Source files, exports and previews have individual SHA-256 checksums in the catalogue.

DWG JSON.gz preserves the source reader's object graph for programmatic use: handles, coordinates, classes and opaque proxy payloads. It is a drawing export under CERN-OHL-S-2.0. The separate JSON catalogue contains CC-BY-4.0 metadata.

The source uses Inventor proxy objects with cached linework. The exports preserve accessible drawing entities and annotations; editable native models and STEP exports are not established. Inspection records expose annotation text with entity handles, entity counts, layout decisions and conversion limitations.

The block audit accounts for the identical entity deficits in eight drawings: ODA omits two repeated template blocks, a sheet border and historical title block. Their stored insertion backlinks are absent from the parsed source graph. This identifies the omitted content; proxy semantics and rendering fidelity remain unverified.

Design only means no installed-hardware association has been established. Provisionally associated requires cited evidence. Confirmed requires a bench check. A match to a thesis drawing is not hardware confirmation.

Cavity-lock electronics (planned)

AG Schaetz plans to lock the LBO and BBO cavities with the digital PID controller developed at PTB and described by Hannig et al. (2018). Later work calls it "PTB-PID". The technical description below comes from public sources. No settings, measured lock performance or hardware assignment are reported for our cavities, and the published source code has not been matched to the firmware on the laboratory units. This plan leaves project parameters and gate status unchanged.

Published design. Hannig et al. lock a Brewster-cut BBO cavity (626 nm → 313 nm) using a Hänsch–Couillaud error signal from a polarization analyser and differential photodiode. The PI output drives a piezo-mounted cavity mirror; the D term is set to zero for cavity locking. The controller is a modified STEMlab 125-14 (formerly Red Pitaya). The PID algorithm runs in the FPGA of a Xilinx Zynq-7010 system-on-chip, independently of the embedded software. It uses two fast analog input channels and two output channels at 125 MS/s with 14-bit nominal resolution. Parameters are set through a web application, a serial connection or a standalone touchscreen and rotary encoder. The paper explicitly states that the board hardware is not open source; the modified application source is publicly available (§IV.C).

Additions to the stock PID. The controller adds a master gain, a second integrator, an output offset, extended parameter ranges and an integrated signal generator. It can save settings and digitally limit its output. An auxiliary intensity input enables automatic relocking by distinguishing TEM00 resonances from parasitic signals, and it provides automatic integrator reset and sample-and-hold. The standalone box amplifies the DAC output eightfold (2 Vpp to 16 Vpp) for the piezo and includes a modification that reduces DAC output noise.

Reported limits and results. The controller's 155 ns group delay suggests a maximum closed-loop bandwidth of a few MHz; effective converter resolution is below 14 bits (§IV.D.2). This is a controller-delay estimate: the published piezo connection also includes a 21.2 kHz low-pass filter (§IV.C.1). In Hannig's cavity, a broad resonance near 17 kHz set the upper limit for locking bandwidth; the authors attribute it provisionally to the mirror, piezo actuator and holder (§V.B). They report 130 h of uninterrupted lock and, in a separate acceleration test, lock retention up to about 1 g with output-power variation at the 10 % level (§V.A, C).

Friedenauer (2006) reports a similar loaded piezo resonance of about 18 kHz for the LBO cavity (§3, p. 372). That resonance is not a measurement of closed-loop bandwidth. Neither paper establishes the bandwidth of our planned locks; that requires measurements of the assembled systems.
